# Security Policy

## Supported versions

Security fixes are prioritized for actively maintained releases and the default development branch.

Check the repository's releases for the currently maintained versions.

## Reporting a vulnerability

**Do not report security vulnerabilities through public GitHub issues.**

Use GitHub's private security advisory/vulnerability reporting mechanism when enabled for the repository. If it is unavailable, contact a project maintainer privately using the contact information published by the repository.

Include:

- A clear description of the vulnerability.
- Affected package(s) and version(s).
- Steps to reproduce.
- Potential impact.
- A minimal proof of concept when safe.
- Suggested mitigation, if known.

Remove secrets, credentials, personal data, and unrelated sensitive information.

## Response process

Maintainers will make a reasonable effort to:

1. Acknowledge the report.
2. Validate and investigate it.
3. Determine affected packages and versions.
4. Develop and test a fix.
5. Coordinate disclosure where appropriate.
6. Publish a security advisory where appropriate.

Please allow reasonable time for investigation before public disclosure.

## Dependency vulnerabilities

If a vulnerability originates in a third-party dependency, report it through the upstream security process and notify hookbase maintainers when hookbase is affected.
